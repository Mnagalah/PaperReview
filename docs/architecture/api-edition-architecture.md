# API 在线版首版架构

状态：API 方案，尚未实施。比赛版本地模块已拆分，见[模型模块](model-modules.md)。日期：2026-11-05。

目标是正常作业忠实、自动、高效地完成，不先建设 Agent 平台。本稿替代此前的多 Agent、通用任务图草案，作为首版范围依据；模型工具调用能力的研究结论仍保留，但不成为首版运行前提。

## 1. 先固定不能退让的结果

- 比赛版 v0.1.2 与原有三个本机模型不动。在线版拟从该标签分支，独立安装、设置和数据目录。
- 在线版 OCR、内容理解 API 必配，支持 DeepSeek 与 OpenAI 兼容；Jev 可关闭、用本机或接专用 API。
- OCR 保留实际错拼、语法、大小写及标点。先整页识别，再覆盖全部检测词区独立读字，不以省调用为由只检查少数疑词。
- 审核只根据最终转写的全文语义生成批注，不读取照片或改写原文。
- 正常作业无需逐字人工确认；确实难以辨认时才提示可读性较差并允许人工介入。服务故障不算字迹差。
- 对照布局、自然字形、物理换行、左右页顺序、阶段显示及现有导入、删除、复制、编辑、导出、重试交互保留。

## 2. 一套共享应用，分别注入模型模块

```text
共享 SwiftUI / AppKit 工作区、WorkspaceStore、图像处理、Repository
                            ↓ ModelModule / ModelSession
              本地模型模块             API 模型模块
              比赛模型配置             服务、模型、密钥配置
              下载与启停               连接与远程请求
              OCR / Jev / 2B           OCR / 基础审核 / 可选 Jev
```

本地模块已独立为 SwiftPM target。API 阶段替换应用入口注入的模块及设置内容，不在工作区散布版本判断，也不复制整套应用。模型模块负责配置、请求、解析、错误、资源管理和模型设置界面；共享部分负责阶段顺序、原文版本、完整度、定位与保存。

任务开始时创建固定配置的会话，设置变化只影响后续任务。原有本机地址校验不放宽，远程请求由 API 模块独立处理。首版不增加 Coordinator、通用节点协议、工具注册中心或事件总线。

## 3. 正常作业只有一条固定主流程

```text
导入 → 图像处理 → 整页 OCR → 全部词区独立读字
     → Jev（可选）→ 固定原文版本 → 基础审核 → 定位与呈现
```

| 阶段 | 执行约定 | 界面反馈 |
|---|---|---|
| 导入、图像处理 | 复用文件校验、重复提醒、扫描增强、透视处理和原片保存 | 原照片先可见 |
| 整页 OCR | 一张图有两页时按左页、右页固定顺序调用与合并，不并行改变页处理顺序 | 已获得的转写按正确页位显示 |
| 逐词识别 | 沿用现有裁片，每个检测词区独立读字；增强图结果有分歧或读不出时才补读原色图 | 显示实际完成数量，保留疑义开关 |
| Jev | 开启时集中完成候选及整页复核；关闭时直接跳过 | 顶部 Jev 显示来源、结果、失败或未启用 |
| 基础审核 | 对固定版本做全文语义检查，生成候选，再按需批量确认；只有一个审核入口 | 识别原文保留，基础审核独立显示处理中 |
| 定位、呈现 | 本机逐字引用校验、去重、计算位置并保存 | 批注高亮、点击定位、导出 |

首版不拆成两个并行审核 Agent，也不让整页 Jev 与审核交叉运行。前一阶段结束或明确跳过后再进入下一阶段，避免原文尚在变化时生成过期批注。

### 转写保真规则不变

- 行号、模板文字与页/行/词 ID 是结构元数据，不混进正文或审核输入。
- 每个词区结果关联原区域 ID，不能按请求返回时间拼接正文。
- 两轮读字有分歧时，使用原色补读、现有字母数量证据与可用 Jev 比较，不用语义模型自由造一个更通顺的词。
- Jev 对常见正确拼写的偏好不能单独抹掉真实错拼；证据不足保留疑义，不自动把 `suny` 写成 `sunny`。
- 保留未返回、不可读和未定位项。接口未完成不能记成全部已核验，低可信标记也不进入学生原文。
- 没有 Jev 时依据读字证据和覆盖完整性继续，不制造 0/1 分数。空响应、截断或缺项按对应错误处理，不通过反复整篇识别来碰运气。
- 严重难读的作业只在既有有限复识上限内尝试；达到上限后保留结果并提示，不无限等待。

### 基础审核收敛为一个服务

OCR 与审核分开。审核始终获得完整作文和独立的行定位表，不把物理换行当成句子边界。

首版候选方案是一次全文检查，加有候选时的一次批量确认；本机再做逐字引用、重复建议和版本校验。保留已有语义检查的覆盖项与正确用法控制，不因架构简化而删除针对错拼、时态及词义的回归要求。

调用压缩不是上线前提：若这一固定方案达不到现有检出与误报门槛，先保留有效的既有固定检查，再局部优化。不能假定云模型只问一次就必然不漏报，也不靠增加多 Agent 对话掩盖问题。

与未解决读字疑义重叠的建议先保留为待处理项，不直接认定为学生错误。无法定位的引用记录原因，不猜到其他词上。审核失败时保留原文及上一批有效批注。

## 4. 并发只放在不会改变业务顺序的地方

- 作业沿用现有单作业队列，首版不同时运行两份作文。
- 页面仍左后右，审核仍在转写固定后开始。
- 只对互不依赖的词区 HTTP 请求增加有限并发，建议上限 2，作为待测起点。完成后按区域 ID 收集，不改变行序与词序。
- 首版不把多词拼成一张图识别，也不靠合并上下文省请求，避免又把学生错拼拟合成正常句子。后续合批优化须单独证明保真不退步。
- 本机 Jev 保持一个实例和一个队列，不增加模型加载数或未经测量就改推理槽。
- 并发优化以相同模型、样本和质量门槛比较耗时、用量与错拼保留；有退步则保留原请求路径，正常流程仍可工作。

完整度优先于可选重试预算：全部词区都必须实际尝试，不能为达到时间上限而跳过尾部。网络、重试与追加识别分别计数，不用一个不透明的总循环控制整个作文。

调用量按实际工作核算：整页页数为 P、词区数为 W、原色补读为 U、失败重试为 R 时，OCR 请求数为 P + W + U + R。例如单页 50 个词区、没有分歧或重试时是 51 次 OCR 请求；并发 2 只缩短等待，不把计费请求变成一半。基础审核计划为 1 次全文检查，加有候选时的 1 次确认，不增加规划调用。若这条路径的耗时或费用不合适，再单独验证词区合批，不能悄悄删掉第二轮。

## 5. 恢复只围绕现有阶段，不建通用工作流数据库

继续使用作业记录、阶段、失败阶段、原文 revision、逐词结果及审核历史。只补充必要的 API 配置修订与 Jev 状态，不引入通用 NodeCheckpoint、跨 Agent 对话日志或第二套作业状态机。

| 问题 | 行为 |
|---|---|
| OCR 或某个词区请求失败 | 保留其他结果，只重试失败请求；未完成的核验不报完成 |
| 网络临时错误 | 对该请求有限重试，首版建议最多自动重试 1 次；仍失败则保存可重试状态 |
| 鉴权、权限或余额错误 | 明确提示修正配置，不自动循环 |
| Jev 未配置 | 标为未启用，直接继续 |
| Jev 调用失败 | 显示复核失败，保留读字证据并继续审核；可单独重试，不当作低分触发整篇重识别 |
| 审核失败或结果截断 | 保留转写和上次有效批注，仅重试审核，不重新 OCR |
| 暂停、退出、重开 | 保存阶段和已完成词区结果；重开等待用户继续，不自动重新付费调用 |
| 人工编辑或重新识别 | 生成新原文版本；旧审核晚到也不能覆盖新版本 |
| 删除作业后请求才返回 | 沿用已有删除保护，拒绝迟到写入，不重建作业 |

逐词恢复只复用图片版本、区域、OCR 绑定与提示版本相同的已保存结果。不承诺恢复供应商生成到一半的 token，也不承诺网络超时后的再次请求一定不重复收费。

## 6. 配置和本机 Jev

服务只保留名称、类型、Base URL、Keychain 密钥引用和模型 ID；接口差异集中在请求编码、响应解析及错误提示。普通流程不要求服务支持工具调用，不在打开设置时逐项发起收费能力探针。

OCR、审核可分别配置服务，也可共用。运行开始后固定地址、模型与策略；中途修改设置只影响新任务，不能把正在恢复的学生作业悄悄发到新地址。远程只用 HTTPS，不向未配置域名转发密钥或图片。

Jev 保留关闭 / 本机 / API 三种来源。本机模式沿用比赛版官方主模型、投影和运行时下载源，当前约 1.96 GB；只下载这三项，不要求其他本地模型齐备。复用下载进度、速度、暂停、重开续传、重试和删除交互，另提供比赛版安装包入口。

Jev 单独启停，只管理本版启动的实例；可明确连接已有比赛版服务，但不停止该外部实例。默认模型目录独立，用户选择共享权重时检查占用，不删除正在使用的文件。退出在线版先暂停任务与下载，再停止自己启动的 Jev。

云端 Jev 只增加实际协议所需的专用请求适配，不建设通用模型插件平台。现行协议仍需核实后接入验证，不能把普通聊天评分冒充 Jev，也不能把未完成的适配显示为可用。

## 7. 数据和界面只增加必要内容

原片不可覆盖；增强图与坐标版本配套；原始读字、采用原文和审核建议分开保存。仍由现有 Store 统一提交、Repository 原子写入，所有异步回写检查作业存在与原文版本。

在线版使用独立应用标识和 Application Support 根目录，不默认共享比赛版可写数据。模型与接口配置不含明文密钥，日志不记 Authorization；学生照片不放到公开 URL，首次上云说明图片和转写分别发给谁。默认不上传第三方 trace；OpenAI 支持的调用显式设置 `store:false`，供应商留存另行说明。

不增加 Agent 聊天框、任务图面板或“哪个 Agent 正在思考”。老师仍只看到照片、转写、Jev、基础审核；请求数、用量、耗时和拒绝详情放到已有详情入口。

三种对照、同步移动、双指缩放、统一字高和每页左边界照旧；没有足够宽度时展开画布，不额外折行或拉伸字形。紫色识别疑义保留开关，与语言错误高亮区分。

## 8. Agent 的位置：研究保留，首版不依赖

首版不实现自主规划循环、转写修复 Agent、双审核 Agent、通用工具注册与跨 Agent 恢复，也不先建空接口或隐藏实验开关。使用固定模型调用的部分就称为工作流，不改名包装成自主 Agent。

模型工具调用的官方兼容结论不变。如果正常流程跑通后，仍有固定规则解决不了、且反复出现的困难区域，再单独验证一个受限 Agent 是否减少失败、调用数或人工负担；只有有收益才替换该局部分支，不同时重写主流程。

这项取舍是优先保证正常作业，而不是把架构能力当作交付目标。Agent 研究不阻塞 OCR、审核、Jev 下载和现有功能。

## 9. 开发与验收按改动拆开

1. **先完善比赛版。** 完成本地模块拆分并回归正常作业、下载、启停和已有设置；API 暂不实施。
2. **再接 API 模块。** 验证 OCR、内容理解配置和结果格式，复用现有图像处理、结构、定位、呈现和导出。
3. **补齐 Jev 可选路径。** 未配置不阻断，本机可单独下载运行，故障不触发无谓整篇重识别；验证与比赛版隔离。
4. **再加最多 2 个词区请求并发。** 与顺序路径用同样本逐项对照，失败时只恢复受影响请求。
5. **审核准确性单独回归。** 不同时重构原图处理、版面算法和模型运行时，也不把减少调用次数作为降低质量的理由。

| 验收项目 | 必须看到的结果 |
|---|---|
| 正常手写作文 | 不经人工逐字确认，自动完成转写、核验、审核和呈现；各阶段用时可查 |
| 原文保真 | 固定样本的 `suny`、`feeled` 等故意错拼保留，标点/大小写按照片核对，不用参考答案作模型输入 |
| 基础审核 | 检出既有正常样本中的错拼、明显时态、`accept → except`、`since → for`，同时保留正确用法、姓名、英式拼写与合法时间转换 |
| 页面与版面 | 左页先于右页，打印行号不进正文；物理换行、字形与对照功能不退步 |
| Jev 可选 | 无 Jev 可完成；有 Jev 可复核；Jev 失败显示真实状态并允许继续 |
| 错误恢复 | API 超时、限流、审核失败和退出重开保留已完成结果；不无限循环或假报无错误 |
| 困难字迹 | 有限尝试后提示可读性较差；不会把服务启动/网络错误解释成字迹差 |
| 双版本 | 在线版不覆盖比赛版应用、数据、模型或服务 |

耗时和费用在选定 API 模型后按固定样本实测；并发方案不能以检出退步换速度。API 部分仍为方案；本地模块的实施与验证单独记录，不下载新权重。
