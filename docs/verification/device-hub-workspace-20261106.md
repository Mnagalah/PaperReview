# Device Hub 方向：原生三栏与液态玻璃

日期：2026-11-06。用户确认直接按 Device Hub 的方向实现，同时保留固定提示位置、对齐和无两侧关闭按钮。此记录取代上一轮内嵌圆角工作面的结构结论。

**当前状态：用户已确认本轮最终版本，作为本地最新版。** 确认发生在标题栏双击和对照工具点击修复之后；应用入口与暂不上传 GitHub 的约定见[开发与协作](../COLLABORATION.md#当前本地最新版--2026-11-06)。

## 已交付的界面

- 三栏直接组成原生窗口，不再套圆角容器：来源栏 216pt，文稿至少 440pt，建议检查器 300–370pt。初次布局低于 1180pt 时，来源栏变为原生作业选择 popover，文稿和检查器始终保留；连续调窗的缓冲及过渡见下文。
- `WorkspaceSplitView` 使用持久的 sidebar / content / inspector 三个宿主。两个 `NSTrackingSeparatorToolbarItem` 跟随真实分隔线贯通工具栏，没有后补绘制的半截竖线。
- `WorkspaceToolbar` 管理原生窗口工具栏：左侧导入，中间文件名、视图切换及撤销／重做／校对，右侧导出和完成批阅。五种视图在宽窗由系统适配，紧凑布局固定为原生菜单；主动作使用系统 prominent 样式。每个窗口有独立工具栏标识，保存期间撤销／重做保持禁用。
- 原稿菜单只保留一个系统下拉箭头。可读性提示占用菜单下的固定第二行；信息区 64pt、底栏 44pt、正文边距 20pt 保持共同基线。提示出现或消失不推动文稿。
- 待处理／已处理分段控件完整可见。两侧没有手动收合按钮、菜单或快捷键；⌘Return 完成批阅继续可用。
- 玻璃用于系统导航和操作层；作文照片、识别文字和建议正文保持平整阅读面。SwiftUI 继续持有业务状态，AppKit 桥接只负责窗口结构、工具栏和选择 popover。

## 让系统新外观实际生效的构建修复

本机 SwiftPM 的 swiftbuild 引擎虽使用 27.2 SDK 编译，默认链接产物的 `LC_BUILD_VERSION` 却记录 `sdk 14.0`，AppKit 因而采用旧外观。仅传 `swift build --sdk …` 没有修复链接记录。

标准打包入口 `script/build_and_run.sh` 现从 `xcrun --sdk macosx` 获取当前 SDK，并向链接器传入 `-platform_version macos 14.0 <当前 SDK 版本>`。打包前用 `vtool -show-build` 检查记录，异常时不替换原应用。本机产物为 `minos 14.0 / sdk 27.2`，实际窗口已显示系统玻璃工具组。没有修改链接后的二进制。

Apple 的 [Build an AppKit app with the new design](https://developer.apple.com/videos/play/wwdc2025/310/) 是原生工具栏、分栏角色与新材质行为的实现依据。代码保留旧系统控件路径和 macOS 14 最低部署版本；未在 macOS 14 设备上运行。

## 后续：打开日常应用、简化标记

- 已构建并打开日常应用的 `original.png` 作业；当前疑义标记为关闭。`ComparisonView` 和设置页的 `showRecognitionUncertainty` 默认值均改为 `false`，保留已保存的显式选择，不改动识别和审核规则。

## 手动缩窗检查与分栏动效

用户将界面验证窗口缩至 **1015×998pt** 后，实际检查了右上导出／完成批阅、紧凑视图菜单、建议栏分隔和底栏。按钮未裁切或互相挤压，分隔贯通，底栏对齐；导出菜单可打开。预览包原有疑义标记偏好为开，已依用户要求关闭。

跳变修复采用原生分栏动画，而不是重建视图或叠加截图：

- `WorkspaceLayout.compactAfterResize` 保留当前布局至越过双向阈值：缩小到低于 1156pt 收起来源栏，扩大至 1204pt 展开。1180pt 仍用于初次布局。

- 普通拖窗不附加延迟；初次布局、未显示窗口和减少动态效果路径直接定位。

## 标题栏双击与视图工具点击修复

用户报告后实际复现了两个问题：顶部空白处双击不改变窗口大小；宽窗视图组的辅助功能树有五个选项，但屏幕只显示一个图标。通过辅助功能动作仍能切换正文，说明后者是控件显示／点击区域问题，不是阅读状态丢失。

- 窗口改为 `.windowStyle(.titleBar)`，搭配 `.windowToolbarStyle(.unified(showsTitle: false))`。系统继续管理双击和拖动；只隐藏重复标题，不使用自定义全局鼠标监听，不修改系统双击偏好。
- 布局跨过阈值时，仅重新创建视图工具组，由 AppKit 重新测量菜单或分段图标的尺寸；选择与禁用状态从现有 SwiftUI 状态恢复。其他动作项与文稿宿主不重建。220ms 分栏过渡与阈值缓冲保持不变。
- 4 项相关测试通过：工具栏角色和动作、宽窄往返后的分段控件可见宽度与五种视图回调、两项窗口 chrome 检查。可见宽度测试用 `PAPERREVIEW_UI_TOOLBAR=1` 启用；测试调用动作与实际鼠标验证分开记录。

最终预览包的实际交互：

1. **1901×1110pt**：五个视图按钮完整显示；鼠标点击“阅读识别稿”成功，单独原稿、滑动及左右对照动作均改变实际正文。顶部空白处双击放大，再双击还原，只有一处文件名。
2. 用户缩至 **965×1110pt**：点击视图菜单，五种选项完整可见，选择“上下对照”成功。
3. 从该窄窗双击放大至 **3840×2065pt**：五个分段图标完整恢复；再次用鼠标点击“阅读识别稿”成功。切回左右对照，再双击还原至用户窄窗。

证据保存在 `.local-tests/20261106-toolbar-interaction/wide-after-roundtrip.jpg` 和 `narrow-restored.jpg`。预览应用保留打开；日常包同步更新。未切换系统的最小化／无动作等其他双击偏好。
