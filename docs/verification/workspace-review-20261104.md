# 2026-11-04 工作区与正常作文审核

本轮交付是中性灰工作区重排和正常作文的拼写/明显过去时漏报优化。三个指定模型保持不变。正常作文定向回归通过；**通用语义8-case仍只命中2/4个错误，不能把本版标为完整语义验收通过。**

## 实现

- 统一紧凑标题栏，标题为“作业批改 — 原文件名”，保留扩展名；`importedFilename`为向后兼容的可选字段。旧记录按原标题与存储文件扩展名显示。
- 三栏`HSplitView`：左侧来源、中央画布、右侧审核；60pt对齐标题。默认深色，可选择跟随系统，中性灰取代蓝色外壳。审核总数为“N 条建议”，与28pt独立更多按钮分开。
- 批注按原文排序，先显示16pt原词→建议，再给14pt说明；长引用上下排列。保留侧栏导入、删除、重复提醒、复制、编辑、导出、Jev详情、暂停/重试与三种对照。
- 2B先做最小纠错草稿，再进行快速语法与有界全文检查；全文检查最多512思考token。三个内部草稿均对未改动OCR文字做差分，合并相同候选。最终2B以另一个最多512思考token的批量请求逐项返回`apply / keep_original`及语言类别。
- ID、原词引用和UTF16范围由程序生成，不让模型编造位置。模型选择类别，程序提供相应的固定中文类别说明；该说明不冒充逐句推导，也不编造主语或时间短语。它比自由生成理由简短，但细分类别仍有不稳定，例如一次把beautifull归入语法。
- 系统`NSSpellChecker`只提供未确认的拼写线索，不运行系统语法检查、不替代2B语义判断、不写回原文。姓名与有效英式变体不作为US纠错线索。
- 词区整体有疑义时，若具体原词获两路独立图像读字支持，允许对该词显示语言批注；疑义本身仍保留。缺定位、旧证据缺失及真分歧仍暂缓。人工确认可继续困难作业，但不能接受过期原文版本。

使用本机已加载的既定服务，串行测试。手写样本仅复用已保存OCR转写，参考答案只用于断言，不进入请求；没有重跑已验证的OCR/Jev。JSON汇总不包含照片、完整学生原文、机器路径或思考过程。

## 为什么没有采用更快的试验

私有详细记录位于被忽略的`.local-tests/20261104-precision-review/`：

- 单次无思考纠错约3–6秒，能发现suny，却漏掉多数明显时态。
- 仅按物理行检查、逐句焦点检查都未解决继承时间的漏报。
- 仅增加1024思考token更慢，仍漏天气描述的is；512token保留了关键能力。快速与有界全文两次检查的遗漏互补。
- 自由中文解释出现“主语是take”、把时态说成主谓一致、复制别条理由；部分回复还把accept布尔值反向填写，尽管理由说原文错误。小批次和不带思考的单条请求同样不稳定。
- 现采用明确动作枚举、有限类别与有界思考，删除自由解释生成及额外翻译请求。不是把false强制改true，也没有按测试答案自动修文。
