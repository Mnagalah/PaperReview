# 识别风险建议与排队反馈 · 2026-11-06

状态：用户已确认作为日常版 0.1.4（6），并授权同步 GitHub；下列测试及预览证据对应这一已接受候选。已发布的 v0.1.4（5）安装包不变。

## 两个故障的直接原因

1. 用户截图对应的旧作业有 11 条有效文本建议全部存入 `deferredReviewIssues`。该版本转写 `isAligned = false`，89 个文本词中 0 个有可靠照片词区对应；87 个已检查词区均记录为未解决。`ReviewLiteralSupport.canAnnotate` 遇到未定位文本范围立即返回 false，旧界面再用“词区识别仍有分歧，暂不批注”统一隐藏这些提议。此拦截未比较 Jev 分数阈值，不能靠调低阈值解决；缺照片定位也不等于 89 个词都读错。
2. `retry` 已把作业放入队列，但建议列表优先显示旧结果，没有处理状态；无旧结果的 loader 条件仅包含 `isRunning`，不包含 `.queued`。所以两条路径都缺少排队反馈，失败后重试也可能看起来没有响应。

## 当前行为与数据契约

- `AssignmentRecord.reviewIssues` 汇总当前建议和仍锚定同一转写、逐字引用有效的旧风险建议，去重后按文本位置排序。保留原有存储字段和证据，不迁移或清空旧记录，也不要求重新识别。
- 风险建议在普通列表显示“可能识别有误”标签，可确认、放弃、恢复、撤销和导出。计数、文本标记、下一条选择和完成批阅使用同一个集合；待确认导出保留风险提示。确认后仍不改写学生文字。
- 无效引用或无修改等模型提议在列表内说明具体原因，不再折叠；没有可靠文本位置时不提供无效确认动作。旧记录缺详情如实显示，有唯一精确引用时保留重新定位入口。
- `.queued` 和运行阶段统一归入忙碌反馈：有旧结果时显示固定信息区内的紧凑 loader 与状态；无结果时在右栏水平居中显示相同液态圆点和状态。进入队列立即显示“等待队列中”，开始审核后显示“正在检查基础错误”；失败可重试并继续保留旧结果。
- 排队后禁用重复审核、校对和决定操作；底部状态为“排队中”。没有改动识别阈值、模型提示词或照片几何算法。照片缺可靠位置时仍不画猜测框。
