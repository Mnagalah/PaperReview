# 英文作文 OCR：固定比赛模型，优化结构与视觉核验

核查日期：2026-11-03。工作根：`<project-root>`。

## 结论：值得继续优化，问题不只是模型体量

用户后续明确本项目用于比赛，模型必须固定为 **MiniCPM-OCR F16、Jev Q4、MiniCPM5-2B Q4**。**不新增或替换模型，也不接入 CTC 旁路。** 下文的其他项目用于解释问题、借鉴分行/对齐/评测方法；其权重调查是选型研究记录，不是执行计划。

当前优化顺序改为：**页/行/词结构与覆盖 → 同一 MiniCPM-OCR 的原色/增强、多粒度读字 → Jev 同内容边界核验 → 保留分歧与自动恢复能力**。先修可确认的流程缺口，不以老师逐篇核对补偿识别失败。现有模型的保错领域训练仅是研究方向，尚未授权或开始。

用户给出的几个问题分属不同层，不能混成一个“模型小”的解释：

| 问题 | 已有直接证据 | 应改变的机制 |
|---|---|---|
| 右页续写被放到全文前面 | 当前旧链把整张横向照片当一页识别，几何也全局按高度排序 | 先分左右页，再各页自上而下识别；按页合并，不靠模型猜阅读顺序 |
| 纸上行号混进语法审核 | 旧转写把印刷编号作为普通数字；几何合行也会把边栏编号并入正文 | 原图保留，行号/模板标签作为元数据；模型输入遮除明确模板区域；审核输入把 `id` 与 `text` 分开 |
| 淡笔画、歪斜行与读字分歧 | 词区边界、低对比和生成偏好同时影响 | 保留原色与增强图；稳定词不着色，有分歧/不可定位词区单独突出；疑难词增加原色复读，不把 Jev 当准确率 |
| `suny` 被规范化 | 本项目局部读字可以保留，Jev 仍偏向 `sunny` | 提供不同解码机制的字符证据，测候选召回与候选判别，而不是仅调阈值 |
| 冗余 `is` 被删掉 | `WordAlignment.inventory` 给未匹配物理词 `original/start/length=nil`；`verifyLiteral` 仍跳过无范围项 | 需要插入/删除/替换的覆盖对齐，不能只有替换已有词的接口 |

最后一项包含两重失败：保存的样本词图复读把该 `is` 读成 `23`，并不是“已经正确读出却仅被合并丢掉”。必须同时修字形识别和合并覆盖，不能只修其中一处就宣称解决。

本轮版面实现和实际照片验证另见 `docs/verification/document-structure-20261103.md`；它不替代字符保真验收。上表的插入/删除恢复仍是后续工作；CTC 旁路按比赛约束排除。

## 最接近的现有项目已经验证了方向，也暴露了风险

[`PyaesoneP/vlm-ocr-research`](https://github.com/PyaesoneP/vlm-ocr-research/blob/main/docs/phase4.md)直接研究英文手写作文保错。其小型开发探针中，VLM 原样保留 12/21 个错误片段，单词裁切复读为 13/21；独立 GFCN CTC 可以把实际错误形式排首提高到 17/21。不过宽松自动选词又损伤了 22/219 个干净记录。因此值得借用的是**独立光学候选、分阶段计分和正确对照**，不是照抄阈值或宣布“组合两个模型已解决”。该探针的真实照片未完整公开，不能直接完整复跑。

[Gold 等 BEA 2023 论文](https://aclanthology.org/2023.bea-1.28/)直接研究保留学生手写正字错误，覆盖德语学习者约 1,350 页；配套 [CAWL 指南](https://aclanthology.org/2023.cawl-1.3/)要求保留学生错误而不是写标准答案。它支持本产品的目标与标注规范；语言不同、完整重转写数据不开放，不能直接充当英文产品训练包。

## 外部项目参考：不接入比赛版本

原选型研究核实了 **Kraken 7.1 + PP-OCRv6 small** 的现代英文手写训练覆盖、CTC greedy、歪斜行几何、字符位置和官方 Apple Silicon/MPS 路径。公开识别权重 **13,065,380 bytes、约 3.24M 参数**，代码与该权重均标 Apache-2.0；这只是权重大小，不是 Python/Torch 依赖总量或峰值内存。比赛版本不下载或接入它。[官方发布](https://github.com/mittagessen/kraken/releases/tag/7.1)、[发布者模型元数据](https://zenodo.org/api/records/21788405)

**Teklia/PyLaia IAM 无外部 LM** 作第二对照：英文现代手写 checkpoint 42,671,836 bytes，模型卡 MIT，官方有字符/词级 CTC 对齐与 CPU 解码文档；Mac 依赖组合和 MPS 未在本机验证。[模型卡](https://huggingface.co/Teklia/pylaia-iam)、[解码文档](https://doc.teklia.com/pylaia/usage/prediction/)

两者都没有本项目错拼/冗词保留实证。Kraken 模型卡还有混合转写规范、展开缩写等风险；**无外部 LM 不等于无训练偏好**。TrOCR 仍是自回归识别，不作为首选“去归正”方案。完整对照、许可对象与部署未知见 `20261103-small-htr-projects.md`。

研究这类接口时不能只看最终字符串，还需区分字符时间步、位置和失败状态。Kraken 7.1 部分名为 `logits` 的输出实际是 softmax 后概率；候选 CTC forward score 不能不看张量含义就再次 `log_softmax`。强制对齐只能检验已有文字假设，不能自行恢复缺失 `is`。

## 小模型可以改善：已有同体量训练证据

MiniCPM 官方法语 RIMES 手写行教程，在同一 778 行测试上，CER 从 **5.67% 降到 2.98%**，模型不需要变大。教程是全参数 SFT，参考资源 **8×A100 80GB**，不是 Swift/macOS 训练工具，也不是已验证的 24 GiB 本机 LoRA 路径。[官方 LlamaFactory 教程](https://github.com/OpenBMB/MiniCPM-OCR/blob/main/docs/llamafactory_minicpm_ocr_french_en.md)

[GAD-RL 预印本](https://arxiv.org/pdf/2609.38282)在同一 Qwen3.5-2B 上，把 CHAOS 被改词 Micro Recall 从基模 4.02% 提高到 SFT 37.63%、GAD-RL 59.92%。这是“训练目标可以改变忠实性”的证据；数据是印刷扰动、参考训练 8×H100，尚不是本机手写方案。不能与 MiniCPM 的页均值聚合指标直接排高低。

训练若成为必要，标签应是“错误原图 → 原样错误”，把“错误原图 → 规范词”作为困难负例，同时保留正确原图对照。Jev 域适配也要用原样正例与规范化负例；官方 Jev 当前是块级一致性标签，不能直接当词级字符真值。[官方 Jev 训练格式](https://github.com/OpenBMB/MiniCPM-OCR/blob/main/docs/finetune_jev_en.md)

## 下一步试验仍只使用指定模型

同一组裁切固定比较 MiniCPM-OCR F16 的整页、分行、词区原色/增强结果，再单独检查 Jev 是否能区分原样错误与归正候选。不引入 Kraken/PyLaia 或新的推理栈。其他项目的字符后验方法只用于设计对照和定位失败环节，不能写成本项目已具备的能力。

建议 8 组成对字串 × 4 位书写者 = **64 行**，两位用于开发、两位锁定测试。覆盖重复字母、换位、非词、合词、冗余 `is`、重复词，以及正确拼写但语法错误的词。此为待采集的小实验设计，不是已取得的数据；一次性研发金标不进入老师默认批阅流程。

必须拆开：

1. **无标签自由识别**：原字串是否进入候选？
2. **已知二候选诊断**：同一图上，选择器能否区分实际错误与归正形式？这里只测判别上限，不算部署成功。
3. **实际自动合并**：支持替换、插入、删除；是否保留错误且不损伤正确对照？

分别报告错误保留、规范化、漏词、正确词损伤、候选召回、字符 I/D/S 与耗时。若二选一能判对而自由识别没候选，修召回；若候选已存在仍判错，修评分/领域数据；若保错提高却损伤正确对照，自动替换不通过。普通 CER 或一张照片的完整度不能替代这些量。

本次研究未下载新权重、未安装 Python 推理栈或开始训练。论文与项目原始证据分别在 `20261103-verbatim-ocr-papers.md` 和 `20261103-small-htr-projects.md`。
